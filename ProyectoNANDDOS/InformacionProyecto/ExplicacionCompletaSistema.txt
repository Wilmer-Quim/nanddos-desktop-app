# DOCUMENTACION TECNICA COMPLETA DEL SISTEMA NANDDOS

Proyecto: ProyectoNANDDOS
Tecnologia principal: C# Windows Forms sobre .NET 10 Windows
Base de datos: MySQL, base proyecto_nanddos_db
Fecha de documentacion: 10/06/2026

Esta documentacion explica el sistema como si el desarrollador principal se lo ensenara a otro programador que nunca lo ha visto. Cubre arquitectura, carpetas, archivos, librerias, formularios, base de datos, script SQL, conexion MySQL, flujo completo, PDF, errores comunes y mejoras futuras.

Nota: el proyecto quedo reorganizado con una sola version principal ubicada en ProyectoNANDDOS.

# CAPITULO 1. OBJETIVO Y ALCANCE

NANDDOS es una aplicacion de escritorio para una empresa de soporte tecnico y reparacion de computadoras. El sistema permite iniciar sesion, registrar clientes, registrar equipos recibidos, consultar equipos, cambiar estados, ver detalles, registrar entregas y generar comprobantes PDF profesionales.

El sistema trabaja con identificadores visibles para el usuario: CLI-0001 para clientes, LP-0001 para laptops, PC-0001 para computadoras de escritorio, IM-0001 para impresoras y ENT-0001 para entregas. Internamente existen id numericos en MySQL, pero esos ids no son el lenguaje de trabajo del usuario.

Flujo general:
* Abrir programa.
* Validar conexion con MySQL.
* Iniciar sesion.
* Mostrar pantalla de bienvenida.
* Entrar al menu principal.
* Buscar o registrar cliente.
* Registrar equipo.
* Consultar equipos.
* Cambiar estados o ver detalles.
* Entregar equipo.
* Generar o regenerar comprobante PDF.

# CAPITULO 2. TECNOLOGIAS, FRAMEWORKS Y PAQUETES

## Framework
El proyecto usa .NET 10 Windows con Windows Forms. En ProyectoNANDDOS.csproj se configura TargetFramework net10.0-windows y UseWindowsForms true. Esto habilita clases como Form, Button, TextBox, Label, ComboBox, DataGridView, TableLayoutPanel, Panel, GroupBox y MessageBox.

Si se elimina UseWindowsForms, los formularios dejan de compilar. Si se cambia a un target sin soporte Windows, la interfaz de escritorio no funcionara.

## MySql.Data 9.7.0
Permite conectarse a MySQL. Aporta MySqlConnection, MySqlCommand, MySqlDataAdapter, MySqlTransaction y MySqlConnectionStringBuilder. Se usa en ConexionDB, Login, GeneradorCodigo, RegistrarEquipo, Clientes, ListaEquipos y Entrega. Sin este paquete no hay conexion ni consultas.

## BCrypt.Net-Next 4.1.0
Permite verificar contrasenas hasheadas con BCrypt. LoginForm usa BCrypt.Net.BCrypt.Verify. La tabla usuarios guarda password_hash, no texto plano. Sin este paquete el login seguro no puede funcionar.

## iTextSharp.LGPLv2.Core 3.7.12
Permite crear PDFs. EntregaForm lo usa para Document, PdfWriter, PdfPTable, PdfPCell, Image, Phrase, Paragraph, BaseColor, Font, PdfPageEventHelper y PdfGState. Sin este paquete no se generan comprobantes.

## ImplicitUsings
El proyecto tiene ImplicitUsings enable. Por eso muchos archivos no escriben using System.Windows.Forms o using System.Drawing aunque usen controles e imagenes. Si se desactiva, habria que agregar imports manuales.

# CAPITULO 4. ARCHIVOS DEL PROYECTO

## Program.cs
Punto de entrada. Inicializa Windows Forms, prueba conexion y abre LoginForm. Si falla MySQL muestra un mensaje claro.

## ConexionDB.cs
Centraliza conexion a MySQL. Define servidor, puerto, base, usuario y contrasena. Abre conexiones y prueba disponibilidad.

## GeneradorCodigo.cs
Genera codigos visibles consecutivos. Busca el mayor consecutivo existente y devuelve el siguiente.

## ImagenEmpresa.cs
Busca la imagen de NANDDOS, crea controles de logo centrados y devuelve la ruta del logo para PDF.

## LoginForm.cs
Pantalla de inicio de sesion. Lee usuario/contrasena, consulta usuarios y verifica BCrypt.

## BienvenidaForm.cs
Pantalla posterior al login. Muestra logo, mensaje y boton Siguiente hacia el menu.

## MenuPrincipalForm.cs
Ventana principal con barra lateral y panel central donde se cargan los modulos.

## RegistrarEquipoForm.cs
Flujo guiado para buscar cliente, crear cliente nuevo si no existe y registrar equipo.

## ListaEquiposForm.cs
Lista equipos, busca, filtra, copia codigo, cambia estado, muestra detalles, edita y elimina.

## DetalleEquipoForm.cs
Muestra informacion completa de un equipo en solo lectura.

## ClientesForm.cs
Lista clientes, busca, edita y elimina si no tienen equipos asociados.

## EntregaForm.cs
Registra entregas, bloquea duplicados, regenera comprobantes existentes y genera PDF profesional.

## LoginForm.resx
Archivo de recursos de Windows Forms asociado al login.

## ProyectoNANDDOS.csproj
Define framework, Windows Forms y paquetes NuGet.

## ProyectoNANDDOS.csproj.user
Configuracion local de Visual Studio; no contiene logica de negocio.

# CAPITULO 6. BASE DE DATOS

La base se llama proyecto_nanddos_db. El nombre evita conflictos y coincide con ConexionDB.NombreBaseDatos. La aplicacion asume que ya existe.

## usuarios
Campos: id, usuario, password_hash, fecha_creacion. id es clave primaria. usuario es unico. password_hash guarda BCrypt. fecha_creacion usa CURRENT_TIMESTAMP. Ventaja: seguridad y control de acceso.

## clientes
Campos: id, codigo, nombres, apellidos, email, telefono, fecha_creacion. codigo es visible tipo CLI-0001. id se usa internamente para relaciones. nombres/apellidos son obligatorios.

## estados
Campos: id y nombre. Contiene En diagnostico, En reparacion, Esperando repuesto, Listo para entregar y Entregado. Ventaja: se filtra y cambia estado por id, no por texto suelto.

## nomenclaturas
Campos: id, prefijo y descripcion. Contiene LP, PC e IM. El prefijo alimenta GeneradorCodigo para codigos de equipo.

## equipos
Campos: id, codigo, cliente_id, nomenclatura_id, estado_id, fecha_ingreso, marca, modelo, serial, descripcion_problema, repuestos_necesarios, fecha_creacion. Relaciones con clientes, nomenclaturas y estados.

## entregas
Campos: id, codigo, equipo_id, diagnostico, repuestos_usados, costo_total, fecha_entrega, pdf_path, fecha_creacion. Relacion con equipos. No se duplican entregas para un mismo equipo en la logica.

## Claves y restricciones
PRIMARY KEY en id de cada tabla. UNIQUE en usuario, codigos, estados y prefijos. FOREIGN KEY protege relaciones. InnoDB permite transacciones y claves foraneas. MySQL crea indices automaticamente para claves primarias, unicas y foraneas.

Flujo: busca equipo, valida que no este entregado, completa datos, muestra resumen, confirma, inserta entrega, actualiza estado y genera PDF. # CAPITULO 10. GENERACION DEL PDF

El comprobante se genera en EntregaForm.cs con iTextSharp. El metodo GenerarPdf recibe DatosComprobante y ruta de salida. DatosComprobante contiene codigo de entrega, codigo de equipo, cliente, telefono, email, equipo, problema, estado, diagnostico, repuestos, costo y fecha.

CrearRutaPdf crea ProyectoNANDDOS/PDF y usa el codigo ENT como nombre del archivo. AgregarLogoSuperior inserta el logo de IMGNANDDOS. CrearImagenLogoPdf recorta bordes blancos para que el logo quede profesional. AgregarLineaDecorativa dibuja la linea azul/morada. AgregarTituloYCaja dibuja el titulo y la caja superior derecha con codigo y fecha. AgregarTablaComprobante crea la tabla principal con bordes, filas alternas y textos que crecen si son largos. EventoComprobantePdf agrega marca de agua semitransparente y linea inferior. AgregarFirmasPdf crea las dos areas de firma. AbrirPdf usa Process.Start para abrir el archivo generado.

El PDF obtiene datos dinamicos desde el formulario para entregas nuevas o desde MySQL cuando se regenera un comprobante existente. No usa datos fijos de ejemplo.

# CAPITULO 11. FLUJO COMPLETO DEL SISTEMA

1. El usuario abre el ejecutable.
2. Program.Main inicializa Windows Forms.
3. ConexionDB.ProbarConexion ejecuta SELECT 1.
4. Si MySQL responde, abre LoginForm.
5. El usuario escribe NANDDOS y NANDDOS123.
6. LoginForm consulta usuarios y valida BCrypt.
7. BienvenidaForm muestra saludo y boton Siguiente.
8. MenuPrincipalForm abre RegistrarEquipoForm por defecto.
9. RegistrarEquipoForm busca cliente. Si no existe, permite crearlo.
10. Se registra equipo con tipo, fecha, marca, modelo, serial, problema y repuestos.
11. ListaEquiposForm permite buscar, filtrar, editar, cambiar estado y ver detalles.
12. EntregaForm busca por codigo visible, completa entrega y genera PDF.
13. Si el equipo ya fue entregado, no duplica registros; solo regenera comprobante.

# CAPITULO 12. ERRORES COMUNES Y SOLUCIONES

## Error de conexion MySQL
Causas: MySQL apagado, base no creada, password root incorrecto o puerto diferente. Solucion: abrir Workbench, confirmar proyecto_nanddos_db, revisar root/W@qh1 o cambiar ConexionDB.cs.

## Error de login
Causas: usuario mal escrito, hash incorrecto o base equivocada. Solucion: confirmar usuario NANDDOS en tabla usuarios y validar BCrypt.

## Error al registrar equipo
Causas: falta estado En diagnostico, faltan nomenclaturas, problema vacio o duplicado de codigo. Solucion: revisar tablas estados/nomenclaturas y ValidarRegistro.

## Error al eliminar cliente
Si tiene equipos asociados no se elimina. Esto protege integridad. Primero se eliminan equipos si realmente se desea borrar.

## Error de PDF
Causas: permisos en la carpeta ProyectoNANDDOS/PDF, visor PDF inexistente, paquete iTextSharp faltante o logo no encontrado. Solucion: revisar carpeta ProyectoNANDDOS/PDF, paquetes NuGet e IMGNANDDOS.

## Error de imagen
Causas: IMGNANDDOS vacia o extension no permitida. Solucion: colocar PNG/JPG/JPEG/BMP/GIF en la carpeta.

## Textos con caracteres raros
Causa comun: consola con codificacion diferente a UTF-8. Solucion: editar en Visual Studio con UTF-8 y evitar cambiar codificacion de archivos.
